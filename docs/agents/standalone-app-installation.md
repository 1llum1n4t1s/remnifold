# Standalone app installation

インストール経路は 2 つある。**Setup（Velopack）が一般ユーザーの既定である**（[Setup installer (Velopack)](setup-installer-velopack.md) を参照）。その、オーナーが決めた信頼モデル（R2 からの HTTPS、Velopack フィードのハッシュとプラットフォームのコード署名、`gh` を要求しない）は [DESIGN.md](../design/local-runtime-and-distribution.md#setup-installer-velopack) にある。**以下の strict `install` 経路は上級ユーザー向けに残し、削除も弱体化もしてはならない**。この経路は、認証済みの GitHub CLI と CI の公開者ログのウィットネス、`versions/`/`receipts/` と固定実行ファイルの置き換えの契約、Setup のインストールとの共存（アプリフォルダーは別）を、引き続き要求する。**strict 経路は最終版 1.0.32 で凍結されている**（オーナーの決定、2026-11-18）。新しい版は、バージョンタグから、Setup としてのみ公開し、新しい `release/*` ブランチも `releases/<version>/index.json` も作らない。strict のコード（`install`、`--verify-only`）、`ci.yml`（そのパスと `publish-r2`。古いクライアントのウィットネス検証がこれに依存している）、既存の `release/*` ブランチ、`releases/` のオブジェクトは変更せずに保つ。古い公開の実行は再実行しない。

明示的に依頼されたときは、[README.md](../readme/install-the-local-app.md) に従い、`install --version <version>` でアプリをインストールまたは更新する。公開の確認、`--apply`、続けて同じバージョンでの `--verify-only` の順に行う（認証済みのネイティブ GitHub CLI を使い、Codex は使わない）。`--work-root` は、アプリ、設定、リポジトリの各フォルダーの外に置き、リンクされた祖先がないようにする。`versions/`、`receipts/`、固定実行ファイルを手で編集しない。`connect claude-code`（プレビュー）と `--apply` による登録は、依頼されたときだけ行う。これはユーザーの Claude Code の `settings.json` と MCP 登録を変更する。かつての `plugin-update`/`plugin-bootstrap` コマンドは廃止されており、`USE_REMNIFOLD_INSTALL` を返し続けなければならない。

インストーラーを変更するときは、`cargo xtask updater-test --binary <absolute-native-executable> --archive <absolute-platform-archive> --work-root <absolute-external-work-directory>` を実行する。古いクライアントの状態が読める状態に保たれることを確かめるには、`--previous-archive <absolute-old-native-archive>` を加える。その作業ディレクトリにある `local-plugin-update-validation.json` を確認する。

strict 経路での最初のインストール（Setup にはこれらは不要）には、信頼できる Rust のソースビルド、または署名済みの Windows ブートストラップ `velopack/remnifold-bootstrap-<version>-x86_64-pc-windows-msvc.exe`（strict のバージョン 1.0.32 以前）を使う。最初に実行する前に、その Authenticode 署名（ステータス `Valid`、署名者 CN `Open Source Developer Yuichiro Shinozaki`、RFC 3161 タイムスタンプ）を検証する。未検証の R2 のダウンロードは決して実行しない。Unix では `scripts/bootstrap-plugin.sh` を使う。[README.md](../readme/install-the-local-app.md#first-installation) と [DESIGN.md](../design/release-process.md) に従い、GitHub の認証情報を R2 へ決して送らず、生ログやシークレットを出力しない。
