# Storage and provenance

Remnifold 自身のローカルファイルは、Codex や Claude Code のホームには置かない。`native/src/paths.rs` がそれらを解決する。`REMNIFOLD_HOME` が指定されていれば、接続情報 `remnifold.json` をそのルートに、状態を `remnifold/` の下に、アプリを `app/` の下に置く。指定がなければ、Windows では `%APPDATA%\Remnifold`、macOS では `~/Library/Application Support/Remnifold`、Linux では `$XDG_CONFIG_HOME/remnifold`（状態は `$XDG_STATE_HOME/remnifold`）となる。`REMNIFOLD_HOME` のレイアウトは旧 Codex ホームのレイアウトと同じであるため、テストはすべてのプロセスをフィクスチャのホームに向けて分離する。設定フォルダーに接続情報がない場合、初回の実行時に、旧 Codex ホーム（`CODEX_HOME`、既定は `~/.codex`、旧名の順序に従う）から有効なものをコピーする。これは、完全に書き込んだ一時ファイルから、作成専用のハードリンクで行うため、同時に動くフックや MCP サーバーが不完全なコピーを読むことはない。コピーに失敗した場合は、引き続き旧ファイルを読む。キャプチャと想起は、新しいフォルダーと旧 Codex ホームのフォルダー（1.x の名前を含む）から状態を読み、新しいフォルダーにのみ書き込む。サーバーセットアップの状態は `--apply` のときだけ移すため、読み取り専用の計画は何も書き込まない。旧ファイルは削除されず、明示的な `--codex-home` は Codex のセッションを読む場所を選ぶだけである。Codex ホームは、キャプチャとインポートのために Codex のロールアウトの場所を特定する用途として引き続き使われる。

Remnifold は、現在の製品、プラグイン、リポジトリの名前である。旧 Kagayoi Memory と Cloudflare Supermemory の名前は、読み取り専用の接続、環境、状態の別名である。名前を変更した GitHub リポジトリは、元の正規のプロジェクト識別と、既存の `kagayoi_memory` の出所ラベルに対応づけられ、永続化された `sm_client` の値は互換用のメタデータとして残る。通常の運用で有効にするのは新しいプラグインだけである。既存のサーバーエンドポイントと Cloudflare のリソース識別子は、別途承認されたデプロイまたは移行が行われるまで維持される。

ローカルクライアントは、完了したタスクのレコードを、決定的な v2 のキャプチャキーとカスタム ID とともに、共有の `memories` コンテナに保存する。サーバーは最初の挿入時に UUID を割り当て、同じカスタム ID が再試行されたときはそれを保持する。リポジトリの識別は、プロジェクトの出所として別に保存され、新しい保存領域を分割しない。永続化された `metadata.sm_project_id` フィールドは、`metadata.project` と並んで 1.x の互換契約として保持され、現在の製品名ではない。既存のレコードはサーバー ID と物理コンテナを維持し、キャプチャは、一致する有効な旧レコードを移動せず再利用する。忘れられた旧レコードは再利用の対象ではなく、忘れられた共有レコードを再試行すると、その正規の行が復元される。手動の保存も既定で `memories` に保存し、明示的な `containerTag` があればそれが保存先を上書きする。手動の forget は、ドキュメント ID または正確な保存内容を受け付け、明示または既定のコンテナに限定される。ID は、指定されたコンテナ内の有効なレコードと一致しなければならない。

## 検索と補強の移行

- 0006 は FTS の更新を内容か物理コンテナの変更に限る。0007 は統合の来歴/コンテナのフォールバック式に索引を付け、資格規則は変えない。
- 0016 は4つの `memories` UPDATE トリガーを `AFTER UPDATE OF` に限定する。状態列だけの更新は重い本体を準備しない。`WHEN` の列は `OF` にも含め、`rowid` は更新しない。発火順を保つ。
- 0017 は custom ID とベクトル照合の索引を加える。コードで強制するのは `replaceFacts` の `idx_facts_identity` だけ。
- 0018 は capture 衝突の無効化を空ビュー上の1つの INSTEAD OF トリガーに集める。R（兄弟）、S（依存要約）、P（ピア）を文ごとに再評価し、実体化しない。既存ビューの変更時は展開式も直し、同値性を確かめる。依存連鎖でのトリガー深さは3から4に増える（workerd の測定上限10、D1 本番は未確認）。戻すには新しい移行を使う。
- 0019 は統合ソースのカバリング索引に替える。対象の集計は、生きた全行に検索射影があることを前提とする。
- 0020 は埋め込みの再試行表と候補索引を加え、Worker より先に適用する。

整理の単一行判定はメモリ ID をバインドし、UNION ビュー全体の構築を避ける。忘却と整理の掃除は重ならない2分岐で、hidden が生存行だけというビュー定義に依存する。

0017 の索引は `idx_memories_custom_id` と `idx_memories_vector_sweep`、0019 は `idx_memory_consolidation_sources_lookup`、0020 は `idx_memories_embedding_backlog`。
