# Local app integration

アプリは管理者権限なしでユーザーごとにインストールされます。場所は、Windows では `%LOCALAPPDATA%\Programs\Remnifold`、macOS では `~/Library/Application Support/Remnifold/app`、Linux では `$XDG_DATA_HOME/remnifold`、または `<REMNIFOLD_HOME>/app` です。検証済みの各バージョンは一度だけ `versions/<version>` に展開され、内容の異なる既存のバージョンフォルダーが置き換えられることはありません。`bin/remnifold(.exe)` はすべての登録が参照する固定の実行ファイルで、`receipts/` はオフライン検証用のレシートを保持し、`current.json` はインストール済みのバージョンを指します。置き換えでは、検証済みの新しいファイルを書き込み、名前を変更して所定の位置に入れます。Windows では実行中の実行ファイルを上書きできませんが名前の変更はできるため、古いファイルを先に脇へ移し、使われなくなってから削除し、結果は `restartRequired` を報告します。接続ファイルは `remnifold.json`、`kagayoi-memory.json`、`supermemory.json` の順に、まず設定フォルダーで、次に以前の Codex ホームで読み込まれます。セットアップは現行のファイルを書き込み、以前のファイルは残します。環境変数による上書きとユーザー向けのアップグレード手順は [README.md](../readme/upgrading-from-1-x-names.md) に記載しています。

`connect claude-code` は固定の実行ファイルを登録します。MCP サーバーは公式の `claude mcp add --scope user` を通して登録し（CLI が `PATH` にない場合はそのコマンドを表示します）、`PreToolUse`、`SessionStart`、`UserPromptSubmit` と非同期の `Stop` の各フックは、パッケージのマッチャー、タイムアウト、ステータスメッセージのまま、Claude Code の `settings.json` へマージします。自動想起が off のとき（`recallMode` はフックと同じ `read_settings` で読み、未設定は `off`）、`SessionStart` と `UserPromptSubmit` は登録されず、これらに対する Remnifold の既存のエントリは削除されます。`Stop` と `PreToolUse` は常に残ります。`PreToolUse` フックは、`sessionId` が `"current"` である `search_memory` の呼び出しも書き換えます。`updatedInput`（入力全体を置き換える）を返し、ペイロードの `session_id` を設定して、他の引数は変更しません。マッチャーは `^mcp__remnifold__|^mcp__toolport__toolport_(call_tool|run_script)$`（ステータスメッセージは "Checking tool access..."）で、直接登録した `mcp__remnifold__*` に加えて Toolport ゲートウェイの `mcp__toolport__toolport_call_tool` と `mcp__toolport__toolport_run_script` も対象にします。後者は `tool_input.name` が「registry 上の Remnifold サーバーの id（`[A-Za-z0-9_]` 以外を `_` に置換）`__` 読み取り専用の7ツール」に完全一致するときだけ同じ許可と置き換えを行い、`arguments` だけを置き換えます。registry はツール名が一致したときだけ環境変数と既定パスで解決し、有効・無効やプロファイルは見ません。別サーバーの同名ツール、書き込みツール、registry を読めない場合は `{}` を返します。`run_script` は、ペイロードの `permission_mode` が `"auto"`（判定なしの `updatedInput` は拒否されるため）のとき、または元の `script` の先頭（空白と `//`・`/* */` コメントを除く）が `"use strict"` のとき（前置きで strict が外れるため）は何もせず `{}` を返し、`"current"` は従来の固定エラーになります。それ以外では `tool_input.script` に `current` と `search_memory`（または `searchMemory`）が含まれ、registry に Remnifold のサーバーがあるときだけ扱います。許可（`permissionDecision`）は出さず（スクリプトが読み取り専用だけを呼ぶとは証明できないため）、`script` の先頭へ、元の先頭行へ改行なしで連結した1行の JavaScript を足した `updatedInput` だけを返します（`data`・`input` などは保つ。足した後が 256 KiB を超えるときは何もしない）。この前置きが、実行時に `toolport.call` / `callAsync`（`servers.<id>.*` のスタブと `callAll` もこれを経由）へ渡る `<前置き>__search_memory` / `<前置き>__searchMemory` の `sessionId: "current"` を、ペイロードの `session_id` に置き換えます。ゲートウェイの Claude Code 登録名が `toolport` でない場合と `toolport_fetch_result` は対象外で、前置きが効かないときは `"current"` のまま届いて固定エラーになるため、セッション ID を明示します。実装は `native/src/hooks.rs` と `native/src/toolport.rs` です（後者は Edictora の正本の複製）。マージは、そのイベントについて Remnifold を実行するコマンドのエントリ（以前のランチャーを含む）だけを置き換え、他の設定はすべて保持し、不正な形式のファイルは拒否し、一度だけのバックアップを保持します。Claude Code は Windows では Git Bash を通してフックを実行するため、コマンドはスラッシュ区切りの実行ファイルのパスを引用符で囲み、引用や展開に使われる文字を含むパスは拒否します。`connect <tool> --remove` はその逆の操作です。コマンドが Remnifold を実行するエントリだけ（`--executable` を付けた場合は、そのファイルを指すものだけ）を削除し、空になったイベントと `hooks` を取り除き、`claude mcp remove remnifold --scope user` または `codex mcp remove remnifold` を実行します。`connect codex` は、Codex にはプラグイン外でフックを登録する公式の方法がないため、`codex mcp add` を通して MCP サーバーだけを登録します。`.codex-plugin/`、`.mcp.json`、`hooks/` はソース資産として残りますが、インストールの経路ではありません。

プラットフォームアーカイブの作成と、Windows の `commandWindows` ランチャーは [release-process.md](release-process.md#パッケージとフックのランチャー) を参照。
