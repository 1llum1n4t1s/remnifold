# Provisioning

ネイティブの `server-setup` コマンドは、Cloudflare REST による探索、再開可能なプロビジョニング、移行、デプロイ、エンドポイントの検証を扱う。既定は認証付きの読み取り専用の探索で、`--apply` で変更が有効になる。認証には `CLOUDFLARE_API_TOKEN` か `--token-stdin` を使い、Wrangler の OAuth 資格情報はインポートしない。明示された名前は、`--config` で渡された既存の JSONC 設定より優先され、その入力が上書きされることはない。明示された名前がない場合、探索は `remnifold`、次に `kagayoi-memory`、次に `cloudflare-supermemory` を再利用する。設定されたリソースの識別子は、選択されたアカウントと、探索されたリソースに一致しなければならない。既存のバインディング、スケジュール、ルートは保持され、互換性のない設定は、黙って置き換えられずに拒否される。カスタムドメインとルートの変更には、それに対応する追加の Cloudflare の権限が必要である。

再開用の状態は、リポジトリの外の、アプリの設定フォルダー内の `server/config.json`（以前の Codex ホームからは `--apply` のときだけ移される）か、`--state` で渡された外部の絶対パスに保存される。リンクされた祖先を持つパスと、設定の入力を状態の出力として使うことは拒否される。生成されたリソースの識別子と資格情報は、ソースの資産ではない。

移行はデプロイとクライアントの変更より前に実行される。追加型の OAuth 移行は、既存のドキュメント、物理スペース、来歴、`sm_*` メタデータを保持する。メモリキーを渡すと、認証付きのセッション、リモート MCP の初期化、必須ツールの検出の検証が有効になる。ローカルのキーがない場合、セットアップは既存のシークレットを保持し、認証付きの検証がスキップされたことを報告する。失敗した手順は、同じリソースに対して再開できる。capture のレシートは既存の Codex ホームに残り、サーバーへは移行されない。
