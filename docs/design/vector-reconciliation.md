# Vector reconciliation

Vectorize のエントリはリビジョンを持ち、D1 が権威を持つ。検索と照合は最大20 ID のバッチを使う。忘却と置き換えは削除を予約し、15分ごとの照合は AI が無効でも再試行する。D1 のガードに負けた upsert を掃除し、復元と競合した削除では現在のベクトルを再登録する。外部でまだ見える削除は後の照合にも残す。`reconcileVectors` は保存済みの埋め込みだけを扱う。

## 欠けた埋め込み

`persistMemoryEmbedding` は埋め込みの完了時に保存してベクトルをキューに入れる。`waitUntil` の打ち切り（上限は約30秒との推定で、本番ログ未確認）より前に終わった埋め込みは残る。

`retryMissingEmbeddings` は15分 cron の照合後に、20分以上更新がない、生きた補強対象で埋め込みのない行を拾う。`pending`/`processing`/`failed` の行を試行回数の少ない順、新しい順に最大10件選び、整理要約、opt-out、整理で隠れた行を除く。18:00 UTC の cron では動かない。前段の失敗でも実行し、その例外は最後に再送出する。

移行 0020 の `memory_embedding_retries` はリビジョンごとに最大5回、15分・1時間・6時間・24時間の間隔を持つ。AI の呼び出し前に条件付き upsert で権利を確保する。各行60秒で打ち切り、1日960回以下とする。事実とトピックは再試行しない。`topic_revision` と `updated_at` は変えない。書き込み前に同じ版、現在の生存、補強許可を確認し、遅れた結果を捨てる。

失敗は `persistMemoryEmbedding` を通らず、同じ版を確保し、まだ埋め込みがない行だけに状態と伏せ字エラーを書く。通常経路が先に成功した行を失敗に戻さない。成功時は再試行を除き、埋め込みだけの切り詰められていないエラーを消す。0020 は Worker より先に適用する。未適用なら再試行だけが照合後に失敗し、最後に例外を送出する。

## 整理の要約と可視性

整理要約は埋め込みだけの CAS 付き上限再試行を使い、事実を作らない。試行トークンで遅れた書き込みを防ぎ、現在のトークンで D1 を直す。期限後の回復は未返却の AI 呼び出しと重なりうる。一般の補強契約は変えない。

AI 有効時、埋め込みを持つ原本は、必要な全要約の埋め込みと索引済みベクトルがそろうまで見せる。無効時は字句の完全網羅で隠すが、AI を再び有効にすると準備まで再表示する。網羅済みなら prepare では選ばない。明示 opt-out の旧記録に埋め込みが残れば先送りする。

照合は置き換え準備まで原本ベクトルを保ち、準備後に削除する。隠れたベクトルが topK を占めうる間、上限200行の D1 フォールバックは索引済みも含める。未照合の判定が失敗した場合も広い側を使い、全て照合後は索引されていない行だけを調べる。原本が再表示されたら FTS と直接取得は即時、ベクトルは保存済み埋め込みから非同期に戻す。15分間隔は完了期限ではない。
