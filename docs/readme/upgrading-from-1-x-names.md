# Upgrading from 1.x names

Remove an installed `kagayoi-memory`, 1.x `cloudflare-supermemory` or `remnifold` Codex plugin and install the standalone app. The client reads `remnifold.json` first, then `kagayoi-memory.json` and `supermemory.json`, in its configuration folder and then in the former Codex home. `REMNIFOLD_API_URL` and `REMNIFOLD_API_KEY` are the normal environment variables; the former `KAGAYOI_MEMORY_*`, `SUPERMEMORY_API_URL`, `SUPERMEMORY_CODEX_API_KEY`, and `CLOUDFLARE_MEMORY_API_KEY` readers remain for compatibility. Run `remnifold setup` to write the normal `remnifold.json` while keeping the previous files. Existing capture receipts and recall state remain readable from the former product folders. Server setup reuses resources named `remnifold`, then `kagayoi-memory`, then `cloudflare-supermemory`; explicit resource names always win. Changing the local app does not deploy a Worker or move a remote database. Existing document IDs, capture IDs, project provenance and persisted `sm_*` metadata remain unchanged. Storage compatibility details are in [DESIGN.md](../design/storage-and-provenance.md).
